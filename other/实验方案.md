# AI 辅助识别代码架构评测方案说明

## 这份文档的定位

当前目录中，评测执行以这份主文档为准：

```text
架构识别工具评测执行方案.md
```

本文件只作为入口说明，帮助人快速理解评测目标和文档关系。不要让执行 agent 同时依据多份方案执行，否则容易出现规则冲突。

## 为什么不再拆成“实验方案”和“执行方案”

这次评测的目标不是写一个只给人看的研究设想，而是要在内网下载后直接使用：

1. 人能看懂评测准备做什么、为什么这么做、最后如何选型。
2. Agent 能拿到源码仓库后，自动扫描仓库、生成任务、构建参考答案、执行对比、评分并输出报告。

因此更适合使用一份完整主文档，同时包含：

- 评测目标
- 实验臂定义
- 仓库分层
- 自动任务生成
- 弱真值/参考答案池构建
- Baseline 与四种工具执行规则
- 多模型、多轮测试矩阵
- 评分体系
- 最终报告模板
- 可直接给 agent 的执行提示词

## 关键设计变化

早期方案假设可以先由熟悉仓库的人制作 `ground truth`。但当前场景里，执行者通常不熟悉仓库，只知道源码已经在内网环境中。

所以主方案已经改成：

```text
多代理独立探索
+ 证据绑定
+ 交叉一致性
+ 工具互证
+ 可验证任务
+ 抽样人工审计
= 可执行的弱真值评测体系
```

也就是说，不要求人提前知道答案；但任何被用于评分的结论，都必须能追溯到源码、配置、测试、静态分析结果或多个独立 agent 的一致证据。

## 被评测方案

共比较 5 个实验臂：

| 实验臂 | 含义 |
| --- | --- |
| `Baseline` | 不用专门工具，只靠普通源码阅读、文件搜索、目录浏览 |
| `GitNexus` | 使用 GitNexus 的索引、图谱、augment、CLI/MCP 能力 |
| `graphify` | 使用 graphify 构建代码/文档图谱并分析 |
| `Understand-Anything` | 使用知识图、layer、tour、domain graph、dashboard/chat/explain |
| `codegraph` | 使用 codegraph 的 context、trace、explore、impact 等图查询能力 |

## 推荐执行入口

给执行 agent 时，直接提供：

1. 源码仓库根目录。
2. 可用模型列表。
3. 可用工具安装方式。
4. 输出目录。
5. [架构识别工具评测执行方案.md](./架构识别工具评测执行方案.md)。

执行 agent 应按主文档第 18 节的总提示词启动。
