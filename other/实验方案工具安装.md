# 实验方案工具安装

## 0. 这份文档解决什么

这份文档说明如何在内网环境安装并接入 4 个架构识别工具：

- `GitNexus`
- `graphify`
- `Understand-Anything`
- `codegraph`

目标是让内部 agent 可以按统一方式调用这些工具，然后执行 `架构识别工具评测执行方案.md` 中定义的 Baseline 与 4 个工具组评测。

本文不负责定义评分方法，评分和实验流程以：

```text
架构识别工具评测执行方案.md
```

为准。

## 1. 总体安装策略

内网部署建议分成两层：

1. `工具安装层`：在评测机器上安装 CLI、MCP server、skill/plugin 文件。
2. `项目索引层`：对每个被测仓库分别构建工具索引，并记录索引耗时、版本、产物路径。

推荐目录：

```text
benchmark/
  tool-artifacts/
    npm/
    pypi/
    git/
    binaries/
  tool-installs/
    gitnexus/
    graphify/
    understand-anything/
    codegraph/
  tool-configs/
    mcp/
    skills/
  runs/
  reports/
```

内网机器原则：

- 不要求运行时访问公网。
- 所有 npm、PyPI、GitHub 依赖应提前下载到内网制品库或离线包目录。
- 每个工具安装后必须执行“版本检查 + 最小仓库 smoke test”。
- 每个工具都要支持两种调用方式：CLI 直接调用，以及 agent 通过 MCP/skill/plugin 调用。
- 每个工具安装、索引、查询失败都要记录，不要人工绕过失败样本。

## 2. 基础环境

建议评测机器具备：

| 依赖 | 用途 | 建议 |
| --- | --- | --- |
| Git | 固定仓库 commit、读取历史 | 必须 |
| Node.js / npm | GitNexus、codegraph、部分插件 | Node 18+ |
| Python | graphify、评测脚本 | Python 3.10+ |
| uv 或 pipx | graphify 隔离安装 | 推荐 uv |
| pnpm | Understand-Anything 本地源码安装时可能需要 | 推荐 |
| 内部 agent CLI | 执行评测 | 需要支持工具调用日志 |
| MCP host | 让 agent 使用 MCP 工具 | Codex/Claude/Cursor/OpenCode 等均可 |

基础检查：

```bash
git --version
node --version
npm --version
python --version
uv --version
pnpm --version
```

如果内网机器不能访问公网，先在外网或制品构建机准备离线包：

```text
npm:
  gitnexus
  @colbymchenry/codegraph

pypi:
  graphifyy
  graphifyy[mcp]
  graphifyy[openai] / graphifyy[ollama] / graphifyy[all] 按需要选择

git:
  Lum1104/Understand-Anything
```

## 3. 内部 agent 接入规范

不管内部 agent 是 Codex、Claude Code、Cursor、OpenCode，还是自研 agent，建议统一抽象成下面几类能力：

```yaml
agent_tooling:
  shell: true
  file_read: true
  mcp: true
  skill_or_instruction_files: true
  command_logging: true
  tool_call_logging: true
```

每个工具都要注册成一个独立 arm，避免工具互相污染：

```yaml
arms:
  - arm_id: baseline
    allowed_tools:
      - shell
      - file_read
      - text_search
  - arm_id: gitnexus
    allowed_tools:
      - gitnexus_cli
      - gitnexus_mcp
      - shell
      - file_read
  - arm_id: graphify
    allowed_tools:
      - graphify_cli
      - graphify_mcp
      - shell
      - file_read
  - arm_id: understand_anything
    allowed_tools:
      - understand_commands
      - understand_artifacts
      - shell
      - file_read
  - arm_id: codegraph
    allowed_tools:
      - codegraph_cli
      - codegraph_mcp
      - shell
      - file_read
```

内部 agent 要遵守：

- 当前 arm 只能加载当前工具的 MCP、skill、索引和产物。
- 正式 run 不能读取 `reference/`、其他 arm 的工具产物、其他 arm 的答案。
- 每次 run 前输出当前可见工具列表。
- 每次 run 后保存工具调用日志。

## 4. GitNexus 安装

### 4.1 离线制品准备

外网制品机：

```bash
npm pack gitnexus
```

将生成的 `gitnexus-*.tgz` 放入内网制品库，例如：

```text
benchmark/tool-artifacts/npm/gitnexus-<version>.tgz
```

如果内网有 npm registry，也可以同步 `gitnexus` 包到内部 registry。

### 4.2 内网安装

推荐全局安装，避免每次 `npx` 冷启动：

```bash
npm install -g /path/to/tool-artifacts/npm/gitnexus-<version>.tgz
gitnexus --version
```

如果机器缺少 C++ toolchain，且可以接受跳过 Dart/Proto/Swift 解析，可使用：

```bash
GITNEXUS_SKIP_OPTIONAL_GRAMMARS=1 npm install -g /path/to/gitnexus-<version>.tgz
```

### 4.3 配置 agent / MCP

通用 MCP 启动命令：

```bash
gitnexus mcp
```

Codex 配置示例：

```toml
[mcp_servers.gitnexus]
command = "gitnexus"
args = ["mcp"]
```

OpenCode 配置示例：

```json
{
  "mcp": {
    "gitnexus": {
      "type": "local",
      "command": ["gitnexus", "mcp"]
    }
  }
}
```

也可以运行自动配置：

```bash
gitnexus setup
```

评测环境更推荐把 MCP 配置写到本次 benchmark 的隔离配置目录，而不是污染用户全局配置。

### 4.4 对仓库建索引

在被测仓库根目录执行：

```bash
gitnexus analyze --skip-embeddings
```

大仓库可加：

```bash
gitnexus analyze --skip-embeddings --workers 8 --worker-timeout 60
```

需要生成 agent skills 时：

```bash
gitnexus analyze --skills --skip-embeddings
```

索引产物通常在：

```text
<repo>/.gitnexus/
~/.gitnexus/registry.json
```

### 4.5 Smoke Test

```bash
gitnexus analyze --skip-embeddings
gitnexus mcp
```

让 agent 发一个最小问题：

```text
请使用 GitNexus 查询当前仓库的主要模块、入口点和最重要的调用关系，并列出工具返回的证据。
```

记录：

```yaml
tool: gitnexus
version: "<gitnexus --version>"
install_ok: true
index_ok: true
mcp_ok: true
index_artifact: .gitnexus/
notes: ""
```

## 5. graphify 安装

### 5.1 离线制品准备

外网制品机推荐使用 `uv` 下载 wheel：

```bash
uv pip download graphifyy graphifyy[mcp] -d tool-artifacts/pypi/graphifyy
```

如果需要文档、PDF、Office、多模态能力，可按需下载 extras：

```bash
uv pip download "graphifyy[all]" -d tool-artifacts/pypi/graphifyy-all
```

纯代码架构评测通常先安装：

```text
graphifyy
graphifyy[mcp]
graphifyy[openai] 或 graphifyy[ollama]
```

### 5.2 内网安装

推荐 uv tool：

```bash
uv tool install --find-links /path/to/tool-artifacts/pypi/graphifyy graphifyy
graphify --version
```

如果需要 MCP：

```bash
uv tool install --find-links /path/to/tool-artifacts/pypi/graphifyy "graphifyy[mcp]"
```

也可用 pipx：

```bash
pipx install --pip-args="--no-index --find-links=/path/to/tool-artifacts/pypi/graphifyy" graphifyy
```

### 5.3 配置 agent / skill

通用安装：

```bash
graphify install
```

Codex：

```bash
graphify install --platform codex
graphify codex install
```

OpenCode：

```bash
graphify install --platform opencode
graphify opencode install
```

项目级安装，适合 benchmark 隔离：

```bash
cd <repo>
graphify install --project --platform codex
```

Codex 还需要确认配置中启用 multi-agent：

```toml
[features]
multi_agent = true
```

### 5.4 对仓库构建图谱

在被测仓库根目录执行：

```bash
graphify .
```

或者让 agent 使用 skill：

```text
$graphify .
```

生成产物：

```text
graphify-out/
  graph.html
  GRAPH_REPORT.md
  graph.json
```

生成 call-flow HTML：

```bash
graphify export callflow-html
```

查询图谱：

```bash
graphify query "show the main architecture modules"
graphify query "what connects auth to database?" --graph graphify-out/graph.json
```

MCP stdio server 示例：

```bash
python -m graphify.serve graphify-out/graph.json
```

如果内部 agent 支持 MCP，可注册这个命令，并把 `graphify-out/graph.json` 指向当前被测仓库。

### 5.5 Smoke Test

```bash
graphify .
graphify query "What are the main modules and how are they connected?"
test -f graphify-out/graph.json
test -f graphify-out/GRAPH_REPORT.md
```

记录：

```yaml
tool: graphify
version: "<graphify --version>"
install_ok: true
graph_build_ok: true
query_ok: true
artifact: graphify-out/graph.json
notes: ""
```

## 6. Understand-Anything 安装

### 6.1 离线制品准备

Understand-Anything 主要以 plugin/skill 形式接入 agent。外网制品机先克隆源码：

```bash
git clone https://github.com/Lum1104/Understand-Anything.git
```

将仓库打包到内网：

```text
benchmark/tool-artifacts/git/Understand-Anything/
```

如果安装脚本需要 npm/pnpm 依赖，也要同步：

```bash
cd Understand-Anything/understand-anything-plugin
pnpm fetch
```

或按内部 pnpm/npm 制品库策略同步依赖。

### 6.2 内网安装

如果内部 agent 支持 Claude plugin 机制：

```text
/plugin marketplace add Lum1104/Understand-Anything
/plugin install understand-anything
```

但内网更推荐使用本地源码安装脚本，避免访问 GitHub：

```bash
cd /path/to/tool-artifacts/git/Understand-Anything
./install.sh codex
```

其他平台：

```bash
./install.sh opencode
./install.sh gemini
./install.sh antigravity
```

如果执行机器不能运行脚本，手动复制 plugin/skill 文件：

```text
Understand-Anything/understand-anything-plugin/
```

到内部 agent 的 plugin/skill 目录，并确保 agent 能识别以下命令：

```text
/understand
/understand-dashboard
/understand-chat
/understand-diff
/understand-explain
/understand-onboard
/understand-domain
```

### 6.3 对仓库生成知识图

在被测仓库中执行：

```text
/understand --language zh
```

或只分析子目录：

```text
/understand src/frontend --language zh
```

常用命令：

```text
/understand-dashboard
/understand-chat How does the main request flow work?
/understand-explain src/main.ts
/understand-onboard
/understand-domain
/understand-diff
```

核心产物：

```text
<repo>/.understand-anything/knowledge-graph.json
```

评测中至少记录：

- 是否生成 knowledge graph。
- 是否生成 layer/tour/domain graph。
- 是否能对指定文件 explain。
- 是否能输出 onboarding guide。

### 6.4 Smoke Test

让 agent 在一个小仓库执行：

```text
/understand --language zh
/understand-explain README.md
/understand-onboard
```

确认：

```text
.understand-anything/knowledge-graph.json 存在
```

记录：

```yaml
tool: understand-anything
version: "<plugin commit or package version>"
install_ok: true
graph_build_ok: true
commands_ok:
  understand: true
  explain: true
  onboard: true
artifact: .understand-anything/knowledge-graph.json
notes: ""
```

## 7. codegraph 安装

### 7.1 离线制品准备

外网制品机：

```bash
npm pack @colbymchenry/codegraph
```

将生成的 tgz 放入：

```text
benchmark/tool-artifacts/npm/colbymchenry-codegraph-<version>.tgz
```

如果使用官方预编译安装脚本，也需要把脚本和二进制包同步到内网制品库。内网评测更推荐 npm tgz 或内部 npm registry。

### 7.2 内网安装

```bash
npm install -g /path/to/tool-artifacts/npm/colbymchenry-codegraph-<version>.tgz
codegraph --version
```

或内部 registry：

```bash
npm install -g @colbymchenry/codegraph
```

### 7.3 配置 agent / MCP

交互式自动配置：

```bash
codegraph install --yes
```

指定平台：

```bash
codegraph install --target=codex --yes
codegraph install --target=opencode --yes
codegraph install --target=cursor,claude --yes
```

打印配置，不写文件：

```bash
codegraph install --print-config codex
```

通用 MCP 启动命令：

```bash
codegraph serve --mcp
```

典型 MCP 工具包括：

```text
codegraph_search
codegraph_context
codegraph_callers
codegraph_callees
codegraph_impact
codegraph_node
codegraph_status
codegraph_files
```

### 7.4 对仓库建索引

在被测仓库根目录执行：

```bash
codegraph init -i
```

如果已经 init：

```bash
codegraph index
```

索引产物：

```text
<repo>/.codegraph/
```

MCP server 会在 agent 连接时做 freshness 检查，并在文件变化后自动同步。评测中仍要记录 cold index 时间和 warm query 时间。

### 7.5 Smoke Test

```bash
codegraph init -i
codegraph serve --mcp
```

让 agent 查询：

```text
请使用 codegraph_context 查看当前仓库的主要入口和相关模块，再用 codegraph_impact 分析一个核心文件的影响范围。
```

记录：

```yaml
tool: codegraph
version: "<codegraph --version>"
install_ok: true
index_ok: true
mcp_ok: true
artifact: .codegraph/
notes: ""
```

## 8. 工具隔离策略

为了保证评测公平，建议每个实验臂使用隔离工作区：

```text
workspaces/
  repo_001/
    baseline/
    gitnexus/
    graphify/
    understand-anything/
    codegraph/
```

禁止 Baseline 读取：

```text
.gitnexus/
graphify-out/
.understand-anything/
.codegraph/
benchmark/reference/
benchmark/runs/
```

工具组只能读取自己的产物。例如 `codegraph` 组不能读取 `graphify-out/`，`GitNexus` 组不能读取 `.codegraph/`。

执行 agent 在 run 开始前应打印：

```yaml
arm_id: codegraph
allowed_tool_artifacts:
  - .codegraph/
forbidden_tool_artifacts:
  - .gitnexus/
  - graphify-out/
  - .understand-anything/
  - benchmark/reference/
```

## 9. 统一安装验证清单

安装完成后，生成：

```text
benchmark/tool-installs/install-report.yaml
```

示例：

```yaml
host:
  os: macos
  arch: arm64
  date: "2026-05-30"
runtime:
  node: "v22.x"
  npm: "10.x"
  python: "3.12.x"
  uv: "0.x"
tools:
  gitnexus:
    version: "..."
    cli_ok: true
    mcp_ok: true
    smoke_index_ok: true
  graphify:
    version: "..."
    cli_ok: true
    mcp_ok: true
    smoke_graph_ok: true
  understand_anything:
    version: "commit ..."
    plugin_ok: true
    smoke_understand_ok: true
  codegraph:
    version: "..."
    cli_ok: true
    mcp_ok: true
    smoke_index_ok: true
```

只有四个工具都通过 smoke test，才进入正式评测。若某工具在某机器无法安装，也要保留失败报告，用于最终可用性评分。

## 10. 给安装 agent 的总提示词

```text
你要在内网环境安装代码架构识别评测所需工具。

输入：
- 工具离线包目录：{{tool_artifacts_dir}}
- 被测仓库 smoke test 目录：{{smoke_repo}}
- 内部 agent 类型：{{agent_platform}}
- benchmark 输出目录：{{benchmark_output_dir}}

请执行：
1. 检查基础环境：git、node、npm、python、uv、pnpm。
2. 从离线包安装 GitNexus、graphify、Understand-Anything、codegraph。
3. 为当前 agent 平台配置每个工具的 MCP、skill 或 plugin。
4. 分别在 smoke_repo 中运行最小索引或图谱构建：
   - GitNexus: gitnexus analyze --skip-embeddings
   - graphify: graphify .
   - Understand-Anything: /understand --language zh
   - codegraph: codegraph init -i
5. 对每个工具执行一个最小查询，确认 agent 能真正调用工具。
6. 生成 benchmark/tool-installs/install-report.yaml。

约束：
- 不访问公网。
- 不把某个工具的产物暴露给其他实验臂。
- 每个失败都要记录失败阶段、错误信息、可能原因和是否可重试。
```
